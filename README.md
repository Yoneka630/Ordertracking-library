# 订单追踪工作台

面向 B2B 定制业务的订单全链路追踪工作台 —— **单文件、零依赖、零 CDN**，覆盖「询价 → 报价 → 排产 → 发货 → 回款」，适合年订单量 200 单以内的一人公司 / 小型工作室。

`index.html` 本身就是完整应用：HTML + CSS + JS + 图标全部内联，双击即可离线使用，不需要安装任何东西。

当前版本 **v1.3.5**（单箱体积改为按「外箱尺寸」自动计算：长×宽×高 ÷ 1,000,000、保留三位小数，不再手填，箱规不全时留空）｜ 完整更新记录见 [CHANGELOG.md](CHANGELOG.md)，或打开应用左侧「系统版本」页。

> **1.0 的含义**：不是又加了一个功能，而是把地基定下来 —— 订单 → 报价 → 排产 → 发货 → 回款整条链路跑通，九张表的数据契约不再随手改。往后是修与扩：**破坏数据结构、需要迁移老数据的改动才配叫 2.0**，新功能走 1.x。

## 功能

| 模块 | 说明 |
|---|---|
| 数据看板 | 7 张 KPI（销售总额 / 订单数量 / 实收金额 / 未回款 / 手续费·尾差核销 / 客单价 / 逾期未交付） |
| 订单管理 | **六状态流转**（含**已发货**）、关键字搜索、**思源式条件行筛选**（字段 + 关系 + 值，多行且/或）、**点击列头排序**（升 ↔ 降，列头显示 ▲/▼）、批量修改（赋值 + 查找替换，支持撤销）、**卡片视图**（按合同交期分月成列，字段可勾选显隐）、**行内「发货 / 编辑」**、**表格分页（默认关）+ 列宽拖拽**、详情页＝**可直接编辑属性面板**（顶部仍留关键信息 + 常用操作带） |
| 排产跟踪 | 计划/实际开完工、**状态与进度由所属订单的状态派生**（排产自己**不存**状态）、**点击列头排序**、交期风险分级（已逾期 / 预计晚于交期 / 临近）、**挂起标记**（人工打标，不改订单状态也不改进度）、**卡片视图**（按交期分月、完工单不再倒数）、工单完工后行内直接**发货**、**表格分页 + 列宽拖拽** |
| 发货物流 | 承运方、运单号、发货日期，支持增删改；登记发货后**订单状态自动推进为「已发货」**（已收款 / 已完结不回退） |
| 分批发货 | **一个订单可挂多个出货单号**（单号全局唯一，重复即拦）；详情页给「已发 / 订单 / 出货单号数 / 剩余未发 + 进度条」，新增发货**默认金额＝剩余未发**；累计超订单金额只弹确认不硬拦，超发标红；未发完时订单头标「部分发货」；单号留空由系统生成并**自动避开已占用号段** |
| 回款登记 | 订金 / 尾款 / 实收金额 / 手续费尾差核销，三个口径严格分离，未收金额自动测算 |
| 分次回款流水 | **一笔到账一条记录**：日期 / 金额 / 款项类型（订金·尾款·货款·其他）/ 回款方式 / 流水号 / 备注各记各的；已收＝各笔合计，未收＝金额−已收，回款率按笔推进；回款中心表头改为「已收 / 未收 / 笔数 / 最近回款 / 回款率」，状态新增「部分回款 N%」；老订单（只有订金 / 尾款两个日期）**首次登记时自动补成两笔流水，金额不变**，删空则回到未收；**已有流水的单，订单表单会自动收起「订金/尾款付款日」等老字段**；回款中心另有「应收日」列（口径只留一处），累计到账超订单金额时弹确认 |
| 账期与应收日 | **账期 = 出货后多少天内付款**：10-01 出货、账期 21 天 → 应收日 10-22。账期在**客户档案**维护，订单上可单独覆盖（留空跟随客户）。分批出货**每批各自起算**，回款按先进先出核销，**最早未收清那批的到期日**就是催款日；客户与订单都没设账期时，退回「最后发货日 + 兜底天数」提醒。**合同交期只管交货，不参与回款判断** |
| 交期预警 | T-30 / T-15 天提醒，按风险等级排序；**已发货视为交期风险解除**，转入「发货未收款」关注（交期只管交货，**不参与回款判断**） |
| 导航栏收起 | 侧栏底部「收起导航」按钮：收起后只留图标（224 → 62px），表格区自动变宽；状态存本机（`ot_sb_collapsed`），刷新保持，收起后每项挂 `title` 悬停认页名。手机端（≤920px）侧栏是抽屉，不收窄也不显示该按钮 |
| 订单数量 | **独立手工字段**（选填整数），不从产品明细 / 排产数量推算。订单列表在「交期」右侧有「数量」列（可点列头排序），底部**小计 / 合计两栏也累加数量**并标注「已填数量的 N 笔」；空值显示「—」不写 0。表单、详情属性面板、CSV 导出、卡片字段都可选到；智能录入支持「订单数量：1200 / 数量 500 件 / 共 1200 件 / 3000pcs」 |
| 固定汇总栏 | 表格底部**两条常驻栏**（U9 样式）：上「小计」、下「合计」，**吸底固定** —— 表格内部纵向滚动时表头吸顶、这两行吸底，怎么翻都看得见；横向滚动时两栏跟着走，列右缘与主表逐列对齐。**小计**＝已勾选行 ∩ 当前筛选（没勾选时＝当前页），标签直接写「所选 N 笔 / 当前页 N 笔」；**合计**＝当前筛选结果分页之前的全部行，分页时两栏才拉开差距。金额之外**也累加订单数量**。没有开关、不可关闭；无订单时也照出「0 笔 / ¥0」。卡片视图没有列，退化为底部合计条 |
| 订单数量分析 | 数据看板里独立一块**单量视角**（与按金额统计的卡片互不覆盖）：四个指标 **订单总数 / 商品件数 / 日均单量 / 覆盖地区**；左侧「单量趋势」按**月 / 周 / 日**出柱状或折线，右侧「单量分布」按**状态 / 地区 / 业务员 / 客户**出条形或表格。**时间范围**可切（跟随筛选 / 近 30·90·365 天 / 本年 / 全部），它是在顶部筛选结果**之上再收窄**；**状态 chip 多选**只作用于本模块。两种口径：**订单笔数**按条数、**商品件数**按订单数量字段求和（未填不计入、不拿 0 冒充）。日粒度超过 62 天自动按周聚合并在卡上注明。地区只认客户档案的**国家/地区**，空值归「未填写」，不拿地址猜 |
| 地区分布 | 数据看板里紧跟销售指标的**中国省域图 / 世界国家图**（左上「中国 / 全球」切换）：每个有单的省画一个气泡（位置 = 省会经纬度投影，大小 = 金额或单量，深浅 = 热力三档），右侧是同口径的**省级排行**。指标可在**金额 / 单量**间切，**大区**（华北 / 东北 / 华东 / 华中 / 华南 / 西南 / 西北）可筛（其余省份变暗、排行只留该区），选择存本机。口径**只认客户档案的「省 / 直辖市」**：省留空归「未填写」不上图，境外客户归「海外 · 国家」单列一行也不上图（地图画不出境外，硬塞进某个省就是造假）；港澳台属中国的省级行政区，正常进图。金额先折本位币再合计。底图的国界 / 台湾岛 / 海南岛 / 省会坐标全是常量数据（`CN_OUTLINE` / `PROV_COORD`），渲染与数据解耦，换标准底图只改数据；右下角固定带**南海诸岛**缩略图。**全球图**用 176 国轮廓 + Miller 投影，按客户档案的「国家 / 地区」原文排布（别名归一大陆 / 香港 / Germany；认不出的「欧洲」「中东」归「未定位」不上图），中国整体收成一颗气泡看内外盘比例；地图上方四个指标（覆盖地区 / 金额 / 已回款率 / 客单价）全部取当前筛选的真实字段。手机端地图保底 620px 可横滑，页面本身不产生横向滚动 |
| 附件管理 | 信用证 / 签约合同 / 其他，多文件，走 IndexedDB 本地存储 || 多端同步 | S3 兼容对象存储（七牛 / 阿里云 OSS / 腾讯云 COS / Cloudflare R2 / AWS S3），端到端加密快照 + **本机口令记忆** |
| 思源笔记联动 | 双向同步，支持「直连原库」与「专用同步库」两条路径，列名按「同名优先、中文别名兜底」匹配 |
| 客户档案 | 新增 / 编辑 / 删除，客户维度汇总（订单数 / 金额 / 已回款 / 未回款 / 账期），详情页带**该客户产品**区块。档案含**国家/地区**与**省 / 直辖市**两个地区字段（都是可输入下拉，港澳台写法统一带「中国」前缀），列表与详情可见：国家/地区供「订单数量分析」的地区维度，省/直辖市供看板「地区分布」地图 —— 两级各管一段、互不推导 |

## 快速开始

**方式一：直接打开（最简单）**

双击 `index.html`，用浏览器打开即可。本地功能全部可用。

**方式二：起本地服务（推荐）**

S3 云端同步依赖安全上下文，用 `file://` 打开会被浏览器 CORS 策略拦住，建议起个本地服务：

```bash
# Windows：双击 start-server.bat（自动探测 Node 或 Python）
# 任意平台：
node server.js          # 默认 http://127.0.0.1:8000
```

**方式三：部署到 GitHub Pages**

站点根就是这个仓库的根目录，`index.html` 会被自动识别：

```bash
git init
git add -A
git commit -m "feat: 订单追踪工作台"
git remote add origin https://github.com/<你的用户名>/<仓库名>.git
git push -u origin main
```

然后在仓库 **Settings → Pages → Source: Deploy from a branch → Branch: `main` / `(root)` → Save**，
约 1 分钟后访问 `https://<你的用户名>.github.io/<仓库名>/`。

> GitHub Pages 只支持 `/`（根目录）与 `/docs` 两种发布目录，所以站点入口必须待在仓库根目录 —— 这也是这个仓库根就是应用本身的原因。

发布前建议跑一次 `node deploy.mjs`：它会把 `sw.js` 的缓存版本号对齐到应用版本，并自检站点资源是否齐备。

## 数据与同步

- **数据存放**：默认存浏览器 `localStorage`，附件二进制存 `IndexedDB`。数据跟随「浏览器 + 站点地址」，换设备或换访问地址看不到，这是单文件离线应用的固有特性。
- **多端一致**：在「云端同步」页配置 S3 兼容对象存储，数据会打包成端到端加密快照上传，其他设备填相同配置即可拉取。
- **换设备只需做一次**：
  1. 在 A 设备「导出配置」（勾选「导出时包含 AccessKey 与密钥密文」）；
  2. 在 B 设备「导入配置」；
  3. 首次同步输一次「加密口令」，并勾上 **「在本机记住加密口令」**。

  之后 B 设备**每次打开直接同步，既不用再输口令，也不用重新导入配置**。
- **口令存在哪**：只存在这台设备的浏览器里，用本机设备标识混淆后存放（不是明文，也不是加密，仅为避免肉眼可见）。它**不会写进导出文件，也不会随仓库分发**。换设备请重新导入一次配置并输一次口令；「清除同步配置」会连带清掉它。
- **思源笔记**：在「数据源」页配置。注意思源里**「数据库块 id」与「属性视图 avID」是两个不同的 id**，工作台会自动解析；点「列出思源里的数据库」再点一行即可绑定，不用手抄 id。

## 安全说明

⚠️ 本仓库**不包含任何凭据**。

- 思源 API Token、S3 的 AccessKey / SecretKey 全部在应用界面里填写，只存在于你的本机浏览器中；
- 应用里的默认配置是空壳，仓库里没有任何一份可用配置会被自动加载；
- 测试里出现过的 `AK-TEST-1234` 这类字面量是夹具，不是真凭据。

如果你 fork 后要跑自己的实例，请在自己的实例里重新填写配置，**不要提交到仓库**。

> 本机口令记忆换来的是「便利」，不是「密钥安全」。能让本地脚本读到浏览器存储的攻击者，本来也能读到你的全部业务数据。真正的防护边界是：**导出文件里只有密文，没有口令**。

## 图标与品牌

`icon-192.png` / `icon-512.png` 是 PWA 清单与应用图标，主色取自应用内色板（`#4b77cb` 主蓝、`#3d8f89` 青、`#3d8a5c` 绿）。设计基调：圆角方底 + 白色订单单据 + 右下角语义角标。

## 版本管理约定

版本号是**单一事实来源**：`index.html` 里只有一处 `APP_VERSION` / `APP_UPDATED` / `APP_TAG`，界面标题、侧栏副标题、「系统版本」页都从它取值（HTML 里另有一份同值静态兜底，供无 JS 时显示）。

新增一个版本只需三步：

1. 改 `APP_VERSION` / `APP_UPDATED` / `APP_TAG`；
2. 在 `CHANGELOG` 数组**头部**插一条 `{ v, date, cat, items:[…] }`，并把上一版的 `cur:true` 去掉；
3. 同步 `<title>` 与侧栏 `.s` 那两处静态兜底。

`CHANGELOG.md` 是从应用内的 `CHANGELOG` 生成的，不要手工编辑。
